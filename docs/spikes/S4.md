## Fichiers

Dans `security/kyverno/s4/` (brouillons, pas les politiques finales de J3) :

| Fichier | Contenu |
| --- | --- |
| `ivpol-signature.yaml` | `ImageValidatingPolicy` : règle d'origine + vérification de signature, en Audit |
| `cpol-signature.yaml` | équivalent en `ClusterPolicy` (API dépréciée), pour comparaison |
| `render.sh` | injecte une clé publique dans une politique |
| `pods-test.yaml` | 4 pods : signé, non signé, autre registre, conteneur d'initialisation non signé |

Les deux politiques ont été validées contre le schéma des CRD de Kyverno v1.19.2 (aucun champ inconnu, aucune erreur
de type). Cette validation ne garantit pas le comportement des expressions CEL : c'est l'objet du spike.

## Protocole

Sur le cluster de S1 (ou sur k3d pour aller vite), avec deux images fournies par l'étudiant B : l'une signée avec une
clé **de test** `spike.key` (jamais la clé du projet), l'autre jamais signée.

```bash
# 1. Kyverno, version de chart figée, CA privée fournie au contrôleur d'admission
helm repo add kyverno https://kyverno.github.io/kyverno/ && helm repo update
helm install kyverno kyverno/kyverno -n kyverno --create-namespace --version 3.9.2 \
  --set-file admissionController.caCertificates.data=security/ca/ca.crt
kubectl -n kyverno get pods
kubectl create namespace demo

# 2. API CEL : politique en Audit, puis pods de test
bash security/kyverno/s4/render.sh security/kyverno/s4/ivpol-signature.yaml spike.pub | kubectl apply -f -
kubectl get imagevalidatingpolicies
kubectl apply -f security/kyverno/s4/pods-test.yaml          # en Audit, tout est admis : lire les rapports
kubectl get policyreports -n demo -o wide

# 3. Passer en Deny et rejouer
kubectl delete -f security/kyverno/s4/pods-test.yaml --ignore-not-found
bash security/kyverno/s4/render.sh security/kyverno/s4/ivpol-signature.yaml spike.pub \
  | sed 's/validationActions: \[Audit\]/validationActions: [Deny]/' | kubectl apply -f -
time kubectl apply -f security/kyverno/s4/pods-test.yaml     # capturer les messages de refus
kubectl get pod -n demo pod-signe -o jsonpath='{.spec.containers[*].image}'   # attendu : référence @sha256:

# 4. Ancienne API, pour comparaison (supprimer d'abord la politique CEL)
kubectl delete imagevalidatingpolicy s4-verify-signature
kubectl delete -f security/kyverno/s4/pods-test.yaml --ignore-not-found
bash security/kyverno/s4/render.sh security/kyverno/s4/cpol-signature.yaml spike.pub | kubectl apply -f -   # capturer l'avertissement de dépréciation
# passer failureAction: Audit -> Enforce dans les deux règles, réappliquer, puis rejouer les pods de test

# 5. Procédure de secours (à tester une fois, pour la connaître)
kubectl get validatingwebhookconfigurations,mutatingwebhookconfigurations | grep kyverno
```
