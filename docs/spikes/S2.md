# Spike S2 : quel registre sert nos images en TLS avec une CA privée, et stocke les signatures en OCI 1.1 ?

- **Pilote** : étudiant B — **Date** : 2026-11-05 (environnement de test) ; à rejouer sur `s7-forge` en J2 —
  **Budget** : 2 h
- **Question à trancher** : Zot ou Distribution ? Lequel accepte une CA privée, une lecture anonyme avec push
  authentifié, et sert l'API OCI 1.1 *referrers* lue par Cosign 3 et Kyverno ?
- **ADR nourri** : [ADR-002](../adr/ADR-002-forge-ci-registre.md)

## Environnement

Conteneur Linux de test (pas la machine du labo), binaires des releases officielles vérifiés par SHA-256 :
Zot v2.1.22 (`zot-linux-amd64` puis `zot-linux-amd64-minimal`), Distribution v3.1.2, crane v0.22.1, OpenSSL.
`registry.s7.internal` résolu en 127.0.0.1 par `/etc/hosts`.

## Commandes exécutées

```bash
# 1. CA privée (ECDSA P-256) et certificat du registre, SAN registry.s7.internal
openssl req -x509 -newkey ec -pkeyopt ec_paramgen_curve:P-256 -nodes -keyout ca.key -out ca.crt -days 180 \
  -subj "/CN=S7 CA privee" -addext "basicConstraints=critical,CA:TRUE" -addext "keyUsage=critical,keyCertSign,cRLSign"
openssl req -newkey ec -pkeyopt ec_paramgen_curve:P-256 -nodes -keyout registry.key -out registry.csr \
  -subj "/CN=registry.s7.internal"
printf 'subjectAltName=DNS:registry.s7.internal\nextendedKeyUsage=serverAuth\nkeyUsage=critical,digitalSignature\nbasicConstraints=critical,CA:FALSE\n' > ext.cnf
openssl x509 -req -in registry.csr -CA ca.crt -CAkey ca.key -CAcreateserial -out registry.crt -days 90 -extfile ext.cnf
openssl verify -CAfile ca.crt registry.crt

# 2. Compte de push (bcrypt, exigé par les deux registres)
python3 -c "import bcrypt;print('ci:'+bcrypt.hashpw(b'<mot de passe>',bcrypt.gensalt(rounds=10)).decode())" > htpasswd

# 3. Zot : TLS + htpasswd + lecture anonyme (configuration dans infra/forge/zot-config.json)
zot verify zot-config.json && zot serve zot-config.json
# 4. Distribution : TLS + htpasswd (dist.yml : http.tls, auth.htpasswd)
registry serve dist.yml

# 5. Tests (SSL_CERT_FILE=ca.crt pour les outils Go)
curl --cacert ca.crt https://registry.s7.internal/v2/                    # anonyme
curl -u ci:<mdp> --cacert ca.crt https://registry.s7.internal/v2/        # authentifié
curl https://registry.s7.internal/v2/                                    # sans la CA
crane append -f layer.tar -t registry.s7.internal/s7/demo-app:test      # manifeste au format Docker
crane append --oci-empty-base -f layer.tar -t registry.s7.internal/s7/demo-app:oci   # manifeste OCI
curl --cacert ca.crt https://registry.s7.internal/v2/s7/demo-app/referrers/<digest>  # après signature (S3)
```

## Résultats

| Test | Zot v2.1.22 | Distribution v3.1.2 |
| --- | --- | --- |
| `/v2/` anonyme | 200 | 401 |
| `/v2/` avec le compte `ci` | 200 | 200 |
| Connexion sans la CA privée | échec TLS (code 000) | échec TLS (code 000) |
| Push anonyme | refusé (`UNAUTHORIZED`) | refusé |
| Pull anonyme | accepté | refusé (`UNAUTHORIZED … Action:pull`) |
| Push d'un manifeste au format Docker | **refusé** (`MANIFEST_INVALID`, type `vnd.docker.distribution.manifest.v2+json`) | accepté |
| Push d'un manifeste OCI | accepté | accepté |
| API `GET /v2/<dépôt>/referrers/<digest>` | **200**, index OCI listant la signature | **404** `page not found` |
| Stockage de la signature Cosign 3 (S3) | *referrer* OCI 1.1 | tag de repli `sha256-<digest>` |
| Version *minimal* (sans extensions) | mêmes résultats ; avertissement « ui routes » ignoré | sans objet |

## Surprises et erreurs rencontrées

- Zot refuse les manifestes au format Docker : `docker build` classique, ou buildx avec le pilote `docker`, en
  produit. La CI doit pousser une image OCI (`docker buildx build --output type=oci`, puis push de l'archive). Sinon,
  il faut activer `"compat": ["docker2s2"]` dans la configuration de Zot (non testé).
- Distribution 3.1.2 ne sert pas l'API *referrers*. Cosign 3.1.4 s'en accommode et crée un tag de repli, alors que
  sa documentation demande dans ce cas l'ancien format de signature.
- Avec Distribution, l'authentification s'applique aussi à la lecture : il faudrait des identifiants dans containerd
  (`registries.yaml`) et dans Kyverno.
- Zot et Distribution exigent tous deux des hachages bcrypt dans le fichier htpasswd (`htpasswd -B` ou Python
  `bcrypt`).

## À rejouer sur `s7-forge` (J2)

- Zot en service systemd sous un utilisateur dédié `zot`, sur le port 443 (`AmbientCapabilities=CAP_NET_BIND_SERVICE`).
- Résolution de `registry.s7.internal` par le DNS de `s7-net`, depuis les nœuds k3s.
- Pull depuis containerd avec `registries.yaml` (architecture, section 4.4), sans identifiants.
- Espace disque après 20 builds, puis efficacité du ramasse-miettes (R12).

## Conclusion pour l'ADR-002

Zot est retenu : il sert l'API *referrers*, autorise la lecture anonyme avec un push authentifié et existe en version
*minimal*. Il impose des images OCI. Distribution 3.1.2 a fonctionné de bout en bout (avec le tag de repli) et devient
le Plan B du registre.
