# Spike S3 : Cosign 3 signe-t-il hors ligne avec une clé, et Kyverno 1.19 vérifie-t-il ces signatures ?

- **Pilote** : étudiant B — **Date** : 2026-11-05 (environnement de test) ; à rejouer sur `s7-forge` et le cluster en
  J2-J3 — **Budget** : 2 h
- **Question à trancher** : quelles options faut-il à Cosign 3.1.4 pour signer et attester avec une clé statique, sans
  Rekor ? Où sont stockés signatures et SBOM ? Kyverno 1.19.2 les vérifie-t-il, ou faut-il revenir à Cosign 2.6.x ?
- **ADR nourri** : [ADR-003](../adr/ADR-003-signature-sbom-scan.md) ; pré-test de [S4](S4.md) (ADR-004)

## Environnement

Même environnement que [S2](S2.md) : registres Zot v2.1.22 (port 443) et Distribution v3.1.2, CA privée. Binaires
vérifiés par SHA-256 : Cosign v3.1.4, Syft v1.55.0, Kyverno CLI v1.19.2, crane v0.22.1. Sigstore (TUF, Rekor) **n'était
pas joignable** depuis cet environnement, ce qui a servi de test « hors ligne ». Clé **de test**, jamais celle du
projet.

## Commandes exécutées

```bash
export COSIGN_PASSWORD=<mot de passe de test>
cosign generate-key-pair                                   # cosign.key (chiffrée) + cosign.pub
IMG=registry.s7.internal/s7/demo-app@sha256:7d563b62c430f8a5f2a16abcbe17a09b833536f7fa6439060cdebc77e051b72a

# 1. Signature par défaut
cosign sign --yes --key cosign.key "$IMG"
# 2. Signature sans services Sigstore (forme recommandée par Cosign 3)
cosign signing-config create --out signing-config.json    # aucun service : ni Rekor, ni TSA
cosign sign --yes --key cosign.key --signing-config signing-config.json "$IMG"
#    (forme dépréciée, qui marche aussi : --use-signing-config=false --tlog-upload=false)
# 3. Vérifications
cosign verify --key cosign.pub "$IMG"                                  # par défaut
cosign verify --key cosign.pub --insecure-ignore-tlog=true "$IMG"      # sans journal de transparence
cosign verify --key autre.pub  --insecure-ignore-tlog=true "$IMG"      # mauvaise clé
cosign verify --key cosign.pub --insecure-ignore-tlog=true <image non signée>
cosign tree "$IMG"
# 4. SBOM et attestation
syft registry:"$IMG" -o cyclonedx-json=sbom.cdx.json
cosign attest --yes --key cosign.key --signing-config signing-config.json --type cyclonedx --predicate sbom.cdx.json "$IMG"
cosign verify-attestation --key cosign.pub --insecure-ignore-tlog=true --type cyclonedx "$IMG"
# 5. Pré-test de S4 : CLI Kyverno avec la politique de A et les pods de test (références par digest)
bash security/kyverno/s4/render.sh security/kyverno/s4/ivpol-signature.yaml cosign.pub > ivpol.yaml
kyverno apply ivpol.yaml --resource pods-digest.yaml
```

## Résultats

| Test | Résultat |
| --- | --- |
| 1. `cosign sign --key` par défaut | **échec** : `error getting signing config from TUF … tuf-repo-cdn.sigstore.dev … Forbidden` (Cosign 3 contacte Sigstore même avec une clé) |
| 2. Signature avec `--signing-config` vide | réussie (1,1 s) ; même résultat avec `--use-signing-config=false --tlog-upload=false` (avertissement de dépréciation) |
| 3a. `cosign verify --key` par défaut | **échec** : TUF injoignable (`getting trusted root from TUF`) |
| 3b. `verify --insecure-ignore-tlog=true` | réussie : `The signatures were verified against the specified public key` |
| 3c. Mauvaise clé | refus : `accepted signatures do not match threshold, Found: 0, Expected 1` |
| 3d. Image non signée | refus : `no signatures found` |

| 4. SBOM Syft | CycloneDX 1.7 JSON en 1,3 s (image d'un seul fichier : 0 composant, normal) |
| 4. Attestation et vérification | réussies ; `cosign tree` liste `https://sigstore.dev/cosign/sign/v1` et `https://cyclonedx.org/bom` |
| 5. Kyverno CLI 1.19.2, `pod-signe` | **pass** : la signature Cosign 3 est vérifiée |

## Surprises et erreurs rencontrées

- **Cosign 3 n'est pas « hors ligne » par défaut**, même avec une clé : il télécharge la configuration de signature
  Sigstore par TUF et enverrait la signature à Rekor. Il faut `--signing-config` (fichier versionné dans
  `security/cosign/signing-config.json`) pour signer, et `--insecure-ignore-tlog=true` pour vérifier.
- **En-tête PEM de la clé privée** : `ENCRYPTED SIGSTORE PRIVATE KEY` (identique avec Cosign 2.6.5, vérifié).
  L'ancienne règle de `scripts/check-j1.sh` cherchait l'en-tête des premières versions de Cosign
  (`COSIGN ENCRYPTED PRIVATE KEY`) et ne l'aurait pas détectée : règle corrigée, testée avec une vraie clé.
- `cosign verify-attestation` affiche « Existence of the claims in the transparency log was verified offline » alors
  qu'il n'y a pas de journal : message trompeur, à ne pas citer comme preuve.
- La politique de A ne contrôlait que `images.containers`. Un conteneur d'initialisation non signé était bien refusé,
  mais seulement par `required: true`, sans le message de la politique. Une version qui couvre `initContainers` et ne
  vérifie la signature que des images de notre registre a été testée : 2 refus avec le bon message. Elle est proposée
  à A dans `security/kyverno/s4/ivpol-signature.yaml`.
- Restreindre `matchImageReferences` à `registry.s7.internal/s7/*` **désactive la règle d'origine** : le pod
  `docker.io` est alors admis (testé). Il faut garder `glob: '*'` (R16).

## Conclusion pour l'ADR-003

Cosign 3.1.4 convient avec une clé statique, à condition d'utiliser `--signing-config` à la signature et
`--insecure-ignore-tlog=true` à la vérification (côté Kyverno : `ctlog.insecureIgnoreTlog: true`). Kyverno 1.19.2
vérifie ces bundles en CLI, donc le Plan B Cosign 2.6.5 n'est pas nécessaire à ce stade. Reste à confirmer sur le
cluster, avec le webhook (S4) et la réécriture par digest.
