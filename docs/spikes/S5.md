  vulnérable de l'application témoin ?

## Protocole

Sur `laptopdlamort` (ou `s7-forge` dès qu'elle existe), Docker installé. Trivy v0.76.1 et Syft v1.55.0 installés
depuis les releases officielles, sommes vérifiées (valeurs de `versions.yaml`).

```bash
# 0. Outils, version et somme figées
V=0.76.1
curl -fLO "https://github.com/aquasecurity/trivy/releases/download/v$V/trivy_${V}_Linux-64bit.tar.gz"
echo "c7cbe3137fb8a48a17574bede3dd6beb16742d1e9772929940fc90082c39d9c0  trivy_${V}_Linux-64bit.tar.gz" | sha256sum -c -
tar xzf "trivy_${V}_Linux-64bit.tar.gz" trivy && sudo install -m 0755 trivy /usr/local/bin/trivy

# 1. Base de vulnérabilités : taille et durée, cache vide
export TRIVY_CACHE_DIR=$HOME/.cache/trivy-s5 && rm -rf "$TRIVY_CACHE_DIR"
time trivy image --download-db-only --no-progress
du -sh "$TRIVY_CACHE_DIR"/db ; trivy version          # date et version de la base

# 2. Deux variantes de l'application témoin (app/), image de base épinglée par digest
docker buildx build -t s5/app:saine  -f app/Dockerfile .
docker buildx build -t s5/app:vuln   -f app/Dockerfile.vuln .
docker image ls s5/app

# 3. Scan bloquant, cache chaud (3 fois chacun, garder les 3 durées)
for v in saine vuln; do
  time trivy image --severity HIGH,CRITICAL --ignore-unfixed --exit-code 1 --no-progress s5/app:$v; echo "code=$?"
done
# 4. Sans --ignore-unfixed, pour voir ce que le seuil masque
trivy image --severity HIGH,CRITICAL --no-progress s5/app:saine | tail -20
# 5. Format attaché par Cosign (ADR-003)
trivy image --format cosign-vuln --output vuln.json s5/app:vuln && head -c 400 vuln.json
# 6. SBOM, pour comparer le nombre de composants
syft s5/app:saine -o cyclonedx-json=sbom.json && python3 -c "import json;print(len(json.load(open('sbom.json'))['components']))"
```

Pour la variante vulnérable, épingler une dépendance Python ancienne dont la vulnérabilité HIGH ou CRITICAL **a un
correctif**, puis noter l'identifiant CVE exact relevé par Trivy. On ne choisit pas la CVE de mémoire.
